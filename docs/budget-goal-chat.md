# Budget-based goal chat

Goal conversations now use the current UAE month's saved budget income and planned category targets, including custom categories. Recorded transaction totals never replace the planning baseline. General finance chat and the separate guided Plans form keep their existing behavior.

If the budget is absent or lacks income/targets, chat returns an explicit budget-required state without invoking Ollama. Set up my budget opens the existing budget tracker form in a dedicated chat setup view. Saving returns to the same conversation and sends a resume request; explicit goal facts from earlier user messages can be recovered without asking again. Cancelling preserves the conversation. Session expiry and logout clear it.

The server calculates monthly surplus, the contribution required by the exact future deadline, and shortfalls. Contributions start in the current calendar month and include the deadline month. Scenarios assume the saved monthly budget repeats; missing progress is displayed as an explicit zero-progress assumption, and unlisted costs are excluded. No investment returns are assumed. Zero/negative surplus is distinguished from a goal that can be solved by more time.

Nonessential Entertainment, Shopping and Subscriptions are considered first. Essential Rent/Food/Transport/Bills and common aliases can be offered for discussion afterward, but none of these proposals counts as accepted until the user selects Try this amount. Each initial suggestion is capped at 30% of its category as a starting scenario, not a market-price judgment; the user can enter a different affordable amount. Custom categories remain in the baseline and can be protected; unknown categories are not automatically classified as discretionary.

Cannot reduce protects a category. Keep my budget unchanged protects all categories and shows the possible later deadline. Explore possible cuts reopens discussion. Accepted scenario amounts never edit the saved budget, create expenses/income, or change a saved deadline. Server-side protected canonical categories and UI choices are combined. Budget fingerprints invalidate accepted scenario amounts after income/targets change; actual spending changes do not alter that fingerprint.

Structured goal calculations are returned in AED for the mobile display conversion layer. CNY model context and monetary drafts use the existing normalization. Session-owned goal profiles and choices survive navigation and reset with New chat/sign-out. Arabic and Mandarin labels cover the new flow.

No dependencies or database migrations added. Real Ollama interpretation and device layout require manual testing; mocked model extraction and UI flow checks do not establish model quality.
